## 1. 文件目的

本文件定義一套針對單一研究資料建立的後分類分析平台，可以單機或公開網路靜態網站模式運作。此次平台使用指定 Excel 的逐筆主表建立版本化靜態資料包，提供全文布林查詢、結果列表、Metadata 與 Tag 後分類、累積過濾、版本管理及結果回查，不使用後端資料庫。

本平台程式為目前這批「龍門石窟北魏紀年題記」資料設計，不以任意 Excel 可直接匯入的通用產品為目標。不過，規格與程式應將共用運作邏輯和資料集專屬設定分離，使未來面對另一份 Excel 時，可沿用相同設計與測試框架，並把修改集中在資料設定及必要的專屬功能。

0.18版 Tag 背景色與過濾強調功能已實作；本文件0.19版新增的後分類緊湊控制列亦已完成實作，包含固定「後設資料／內文標籤」分段控制、緊湊排序與清除控制，以及縮減後的提示與分類值列。

### 1.1 本次修訂摘要

0.19版將後分類頂部控制改為「單列模式切換＋緊湊控制列」：原模式下拉選單改為固定的二選一分段控制，介面文字固定為「後設資料」與「內文標籤」；後分類欄位保留一個主要選單，排序與清除全部後分類改為同列的次要控制，並縮減選單、說明與分類值列的高度。詳細規則及驗收見10.1、16.8.1與17.2。

0.18版新增全文 Tag 視覺標示：所有已標記文字持續顯示背景色，符合已套用 Tag 後分類條件的片段再加強標示，並與全文搜尋高亮共同呈現。樣式層級參考本輪使用者附件圖片，具體規則與驗收見9.6及17.6。

0.17版新增含文字標記的全文資料。規格及內部資料模型以 Metadata 後分類與 Tag 後分類區分兩種來源；介面切換顯示名稱自0.19版起固定為「後設資料」與「內文標籤」。Tagname 為分類名稱，`@Term` 為分類值與聚合依據。搜尋與高亮以去除標記語法後的可讀全文為準。以下第7.5、8.7、9.6、10.10及17.5節為相關規格；其中明列建議或待確認的決策尚未核准。前版已確認的介面行為繼續適用。

本版延續後分類值排序、左右獨立捲動與可調寬度、結果區分頁導覽、系統管理收合選單、後分類待套用浮動操作列，以及套用後只顯示已選分類值等需求；並新增以下介面修訂：版本訊息移入系統管理選單、暫不顯示查詢語法說明、移除後分類區標題，以及將「分類欄位」改稱「後分類欄位」。這些均屬共用介面或系統運作邏輯，不寫入資料集專屬的`Data_SPEC.md`。

## 2. 目標與成功條件

### 2.1 目標

1. 使用者可在個人電腦啟動獨立分析平台，透過瀏覽器操作。
2. 平台可匯入符合本資料集既定欄位結構的 Excel，保存原始檔並建立可查詢版本。
3. 使用者可對全文欄位執行包含 `AND`、`OR`、`NOT` 及括號的布林查詢。
4. 使用者可對全文查詢結果反覆執行 Metadata 與 Tag 後分類，逐層縮小結果集合。
5. 所有分類筆數皆由逐筆主表即時計算，不依賴 Excel 內預製的統計資料。
6. 每個查詢結果及分類值均可回查構成結果的全文資料。
7. 同一研究資料可重新匯入修訂版；新版成為現行版，舊版保留供比較或還原。
8. 未來建立另一研究平台時，共用邏輯原則上不變，修改集中於資料集設定、文案及專屬測試。

### 2.2 驗收層級

- 功能正確：查詢、後分類、版本管理及回查結果符合規則。
- 資料正確：原始值不被改寫；多值欄位及特殊狀態正確保存。
- 可追溯：分析結果可追溯至資料版本、原始 Excel、紀錄及欄位。
- 可重現：相同資料、設定及查詢條件產生相同結果。
- 可復原：匯入失敗不影響現行版；舊版可重新設為現行版。

## 3. 範圍

### 3.1 本版納入

- 共用同一分析前端的單機版與公開網路版。
- Excel 匯入、驗證及原始檔保存。
- 資料版本建立、切換、比較及還原。
- 僅針對指定全文欄位的布林查詢。
- 全文命中筆數、完整全文、醒目標示及完整紀錄檢視。
- Metadata 與 Tag 後分類切換及類別下拉選單。
- 分類值勾選、排序、確認套用及累積過濾。
- 已套用條件的顯示、單項移除及全部清除。
- 後分類區與全文結果區的獨立捲動、可調寬度及結果分頁導覽。
- 單機版系統管理功能的收合選單。

### 3.2 本版不納入

- metadata 文字查詢。
- 帳號、登入、角色或多人協作。
- 後端資料庫、查詢API或伺服器端分析邏輯。
- 網路版共用的線上Excel匯入與資料版本建立。
- 網路使用者查詢條件的帳號綁定、跨裝置儲存或雲端同步。
- 依賴使用者提供「分布統計」工作表。
- 欄位新增、刪除、改名或語意變更的自動相容。
- 中文斷詞、同義詞擴展、語意搜尋或模糊搜尋。
- 自動推論或補寫 metadata。
- 未經確認的地圖、關係網絡或其他進階視覺分析。
- 查詢與分類結果匯出。
- 基礎分類分布、統計圖表及其結果回查。
- 特殊狀態排除控制。
- 階層欄位的專屬設定及階層式篩選。
- 各欄位特殊狀態值的專屬設定。

## 4. 使用者與運行環境

### 4.1 使用者

- 本機管理使用者可匯入資料、建立與驗證新版、切換版本，以及執行查詢與後分類分析。
- 公開網路使用者不需登入，可查詢、後分類、切換已發布版本及閱讀完整資料。
- 公開網路版不提供Excel匯入、版本建立、還原或發布操作。

### 4.2 運行方式

- 單機與網路版共用相同的靜態分析前端與版本資料包格式。
- 單機版由本機靜態檔案服務提供給Chrome，不啟用查詢API或後端資料庫。
- 網路版發布至公開靜態網站主機，查詢、後分類、排序、分頁與版本比較均在瀏覽器內執行。
- 新版資料必須先在管理者本機建立並驗證，再將靜態資料包另行發布至網路版。
- 網路版的查詢與後分類狀態只存在當次瀏覽器使用期間，不跨裝置保存。

### 4.3 獨立專案

- 每份研究資料建立一個獨立專案副本。
- 各專案具有自己的資料集設定、靜態版本資料包、原始檔、版本紀錄及介面文案。
- 不同研究專案不得共用執行中的資料版本。

## 5. 系統分層

### 5.1 共用運作邏輯層

不同研究平台原則上共同使用：

- Excel 檔案接收及保存。
- 工作表、欄位及紀錄驗證框架。
- 原始資料與正規化資料的分層保存。
- 全文索引及布林查詢。
- 結果列表、分頁、排序及回查。
- 後分類計數與累積過濾。
- 條件狀態管理。
- 資料版本建立、比較、切換及還原。
- 錯誤處理、記錄及測試框架。

### 5.2 資料集專屬設定層

每個研究平台另外定義，並集中保存於`dataset/profile.json`（機器可讀）、`SPEC/Data_SPEC.md`（人工確認）及`dataset/acceptance.json`（資料專屬驗收值）：

- 平台名稱及研究說明。
- Excel 來源工作表。
- 欄位名稱、欄位標籤及顯示順序。
- 唯一識別欄位。
- 由使用者在建立平台時核准的欄位及功能用途。
- 全文欄位。
- 可後分類欄位及排列順序。
- 單值／多值欄位及多值分隔符號。
- 數值、文字及時間欄位。
- 預設列表欄位及排序。
- 資料專屬測試資料。

### 5.3 分層限制

- 共用程式不得散落寫死本案例的中文欄位名稱。
- 共用程式透過`dataset/profile.json`取得欄位角色；設定以Excel欄名表達，欄位數字索引由設定載入器自動推導。
- 必須理解個別欄位語意的行為，應放在資料集設定或清楚隔離的專屬模組。
- 欄位結構或語意變更時，不在執行階段猜測對應關係，而是停止匯入並回到規格修訂。
- 網站名稱、說明、公開網址及社群分享中繼資料同屬資料集設定，不得在HTML、Python與JavaScript重複維護。
- 正常資料格式移植不得修改查詢、後分類、視覺化或版本核心；只有設定無法表達已核准需求且測試能證明缺口時，才擴充共用程式。

### 5.4 模組化開發與檢查邊界

系統必須採模組化設計，使功能變更可以限定在少數檔案與測試範圍，避免每次開發都需要閱讀、檢查或重測整個專案，並降低AI輔助開發所需的Token用量。

預定模組邊界如下：

1. **資料集設定模組**：`dataset/profile.json`定義`Data_SPEC.md`對應的欄位、類型、驗證、後分類、顯示、排序與網站資訊；`tools/config.py`只驗證並推導索引，不保存案例欄名。
2. **Excel匯入與驗證模組**：只負責讀取、結構驗證、欄位驗證與標準化輸出。
3. **版本資料包模組**：只負責建立、驗證、切換、比較與備份靜態版本。
4. **全文索引與查詢模組**：處理全文索引、布林語法、多輪查詢及命中位置，不理解本案中文欄名。
5. **後分類模組**：處理分類值、可用筆數、分類值顯示排序、同欄位OR、跨欄位AND與累積過濾。
6. **查詢狀態模組**：保存各輪全文查詢、已套用與尚未套用的後分類選擇、各分類欄位的顯示排序、頁碼與結果排序狀態。
7. **介面呈現模組**：依第16.8節已核准的A版外觀呈現，不重複實作查詢或後分類邏輯。
8. **單機啟動與靜態發布模組**：只處理環境差異，不建立另一套分析功能。
9. **全文標記解析模組**：從原始全文產生純文字、標記清單及純文字位置區間；全文索引、Tag 後分類及高亮共用此結果，不各自移除標記。資料集專屬 Tag 名稱及排序由`Data_SPEC.md`提供。

每個模組必須具有：

- 單一、可簡短說明的責任。
- 明確輸入、輸出、錯誤類型與不變條件。
- 獨立入口檔與同目錄說明檔，說明模組用途、公開介面、依賴關係及對應測試。
- 可獨立執行的單元測試與小型固定測試資料。
- 穩定的公開介面；模組外部不得直接存取其內部資料結構。

變更檢查原則：

- 開發前先根據需求追蹤矩陣辨識受影響模組，不預設全專案都需要檢查。
- 正常修改只讀取受影響模組、其公開介面、直接依賴者與對應測試。
- 先執行受影響模組測試；只有公開介面、共用資料格式或跨模組流程改變時，才擴大至整合測試。
- 全專案檢查與完整回歸測試只在發行前、共用格式變更、跨模組重構或無法界定影響範圍時執行。
- 每次修改必須簡要記錄「變更模組、公開介面是否改變、已執行測試、未執行測試與理由」，使後續AI不需重新推導。

## 6. 資料集專屬規格

本開發規格只定義可重複使用的系統行為。本專案的來源檔案、工作表、28個欄位、資料型態、唯一鍵、全文欄位、後分類欄位、結果顯示欄位、排序及欄位驗證，由`Data_SPEC.md`供人核准，並由`dataset/profile.json`提供程式執行；資料專屬驗收數據由`dataset/acceptance.json`提供。

實作若需要資料集專屬資訊，必須讀取`dataset/profile.json`；資料專屬測試必須讀取`dataset/acceptance.json`，不得在共用程式或測試中另寫欄名、索引、檔名或統計常數。三份資料專屬文件內容衝突時不得建置，應以使用者重新核准的`Data_SPEC.md`為依據同步修正兩份JSON；系統操作行為仍以本文件為準。移植流程依`DATASET_ADAPTATION_PROMPT.md`執行。

## 7. Excel 匯入與驗證

### 7.1 首次建立

1. 系統取得指定 Excel。
2. 選擇 Excel 的第一個工作表作為正式資料工作表，其餘工作表一律忽略。
3. 驗證欄位結構是否符合建立本平台時由使用者核准的資料集設定。
4. 驗證唯一鍵、資料型態及多值格式。
5. 顯示匯入摘要、錯誤及警告。
6. 驗證通過後保存原始檔。
7. 建立正規化資料及搜尋索引。
8. 建立第一個可用版本並設為現行版。

### 7.2 平台內重新匯入

1. 使用者選擇修訂版 Excel。
2. 系統先建立暫存匯入工作，不更動現行版。
3. 欄位結構必須與資料集設定一致。
4. 驗證成功後才建立正式版本。
5. 新版成為現行版，原現行版轉為封存。
6. 驗證或解析失敗時，現行版保持不變。

### 7.3 結構變更

出現已核准欄位新增、刪除、改名、角色變更、單值／多值規則變更、分隔符號變更、唯一鍵變更或來源值語意變更時：

- 不自動猜測或轉換。
- 不建立正式版本。
- 顯示欄位差異及問題摘要。
- 提示重新進入資料欄位、功能、程式及測試規格修訂流程。

### 7.4 阻擋錯誤與警告

本節為可跨資料集沿用的共用匯入處理邏輯；各欄位的具體驗證要求及唯一鍵由`Data_SPEC.md`指定。

下列情況為阻擋錯誤，系統不建立新版本：

- Excel沒有任何工作表。
- 第一個工作表無法讀取。
- 欄位數、欄位名稱或欄位順序不符合已核准的`Data_SPEC.md`。
- 欄位名稱重複，或以`(`、`{`開始。
- `Data_SPEC.md`指定的唯一鍵為空白或重複。
- 來源檔超過本開發規格支援的資料規模上限。
- 無法完成資料解析、原始值保存、全文索引或一致版本的建立。

下列情況為警告：

- 一般欄位出現空白值。
- 多值欄位包含空項目、重複項目或疑似使用非核准分隔符號。
- 整數或文字欄位出現無法解析為整數的新文字。
- 資料區中間出現全空白列。

警告只記錄於匯入結果，不阻擋版本建立，也不要求使用者再次確認。警告的判定必須同時依循`Data_SPEC.md`中已核准的欄位類型、單值／多值設定及欄位驗證規則。

### 7.5 含標記全文的解析與驗證（本輪草案）

1. 原始 Excel 與含標記全文逐字保存；另外產生純文字閱讀／搜尋值與 Tag 紀錄，不改寫來源。
2. Tag 紀錄至少保存 Tagname、Term、選用 RefId、標記包住的原文及其在純文字中的起訖位置。同一文件中多個相同標記仍各自保存。
3. `@Term`、`@RefId` 是本規格對「屬性」的表示法；來源實際格式例如 `<person term="揚法師" RefId="A000123">道揚</person>`，不含 `@`。
4. 建議接受 `term` 與 `Term`，統一作為 Term 使用；同一元素同時具備兩種拼法時阻擋匯入，避免歧義。Tagname 大小寫保留且區分；RefId 僅保存，不參與分類合併，也不自動開啟外部連結。
5. 本輪採無巢狀、成對閉合的 XML 片段格式；純文字文件亦可存在。建議遇到巢狀、未閉合標記、重複屬性、空內容或缺少／空白 Term 時阻擋匯入，指出紀錄、欄位及原因，不靜默移除問題標記。缺少 Term 不以元素內文字自動補值。
6. 建議按 XML 規則處理字元實體（如 `&amp;` 還原成可讀的 `&`）；含標記全文中的保留字元須合法跳脫，舊版純文字仍按原文字面讀取。禁止 DTD、外部實體、處理指令及可執行內容；不讀取外部資源，不將來源當 HTML 執行。
7. Term 分類按解碼後完整屬性值相等判斷，不自動去除空白、繁簡轉換或同義合併；全空白 Term 視為空值。單一 Term 中的分號不拆分。
8. Tagname 清單以資料集核准設定為準；建議新增未知 Tagname 時回到規格確認，既定種類在某版本缺席則允許。具體錯誤政策列第19章確認。
9. 純文字與標記位置須使用一致的 Unicode 位置定義；跨 Python 與 JavaScript 時必須處理非基本平面字元，不能混用字元序號與 UTF-16 位移。

## 8. 全文查詢

### 8.1 查詢範圍

- 僅查詢資料集設定指定的全文欄位。
- 本專案實際使用的全文欄位由`Data_SPEC.md`指定。
- 不提供 metadata 文字查詢。
- 查詢以目前資料版本為範圍。

### 8.2 查詢介面

- 提供單一查詢框。
- 使用者直接輸入關鍵詞、運算子及括號。
- 提供「執行查詢」、「清除輸入」及「重新查詢」。
- 本版介面暫不顯示「查詢語法」文字、連結、展開控制或說明區塊；查詢框提示文字及實際語法功能不受影響。
- 「執行查詢」以目前結果集合為範圍執行新的全文查詢，並保留先前全文查詢及後分類條件。
- 「清除輸入」只清空查詢框，既有查詢、後分類條件及結果保持不變。
- 「重新查詢」清除全部全文查詢及後分類條件，回到現行資料版本的資料庫全覽。

### 8.3 語法

- 支援 `AND`、`OR`、`NOT`。
- 支援半形括號 `(`、`)`。
- 運算優先順序為 `NOT`、`AND`、`OR`。
- 括號可改變運算順序。
- 關鍵詞使用連續字串包含比對。
- 不做中文斷詞、詞形變化、同義詞、近似詞或語意擴展。
- `AND`、`OR`、`NOT`運算子不區分英文字母大小寫。
- 雙引號 `"`包住一個字面查詢詞，可包含空白、括號或字面`AND`、`OR`、`NOT`。
- 反斜線 `\`為跳脫字元，使其後一個字元按字面解讀；例如 `\"`表示查詢雙引號本身，`\\`表示查詢反斜線本身。
- 空白查詢表示不增加全文限制。首次查詢時等同目前版本的全部紀錄；在多輪再查詢中不會擴大或縮小目前結果。

### 8.4 查詢語意

- `A AND B`：全文同時包含 A 與 B。
- `A OR B`：全文至少包含 A 或 B。
- `NOT A`：排除全文包含 A 的紀錄。
- `A AND NOT B`：全文包含 A 且不包含 B。
- `(A OR B) AND C`：全文包含 C，且至少包含 A 或 B。

### 8.5 多輪再查詢

- 第一次全文查詢以現行資料版本的全部紀錄為範圍。
- 後續按下「執行查詢」時，以當下已經過全文查詢及後分類過濾的結果為範圍。
- 每一輪新的全文查詢與既有條件之間採 `AND`，因此結果只能維持或縮小，不會擴大。
- 系統須保留各輪全文查詢式及其順序，供結果摘要顯示與重新計算。
- 新一輪有效全文查詢不得清除既有後分類條件。
- 只有按下「重新查詢」才清除全部全文查詢及後分類條件。

設現行資料版本的全部紀錄為 `D`，各輪全文查詢為 `Q1`、`Q2`，目前後分類條件為 `F`：

```text
第一次查詢後：D AND Q1
套用後分類後：D AND Q1 AND F
再次全文查詢後：D AND Q1 AND F AND Q2
重新查詢後：D
```

### 8.6 語法錯誤

下列情況不得執行查詢，且應指出問題位置：

- 括號不成對。
- 運算子缺少運算對象。
- 連續出現不合法的二元運算子。
- 查詢式只有運算子而沒有關鍵詞。
- 出現未支援語法。
- 雙引號不成對。
- 反斜線位於查詢式末尾而沒有可跳脫字元。

語法錯誤不得加入查詢條件，也不得清除既有全文查詢、後分類條件及結果。

### 8.7 含標記全文的搜尋

- 全文索引僅包含可讀文字，不包含起訖 Tag、Tagname、屬性名稱、Term 或 RefId。屬性值若也真的出現在正文，仍可因正文而命中。
- 移除標記語法時保留標記內文字與前後文字的連續關係，不額外加入空白、標點或換行；保留原有文字空白與標點。
- 例如 `比丘尼<person term="揚法師" RefId="A000123">道揚</person>、道積` 的搜尋文本是 `比丘尼道揚、道積`；查詢 `比丘尼道揚` 可跨標記邊界命中，查詢僅存在屬性的 `揚法師`、`A000123` 不命中。
- `AND`、`OR`、`NOT`、括號與累積再查詢全部作用在相同純文字上。Tag 分類可由 Term 選取，但不擴展全文查詢語意。

## 9. 查詢結果

### 9.1 結果摘要

顯示：

- 目前資料版本由第16.8.2節的系統管理選單顯示，不在結果摘要重複呈現。
- 依執行順序排列的全部全文查詢式。
- 各輪全文查詢套用後的結果筆數。
- 套用全部全文查詢及後分類後的目前結果筆數。
- 作用中的後分類條件。
- 結果筆數置於全文結果區上緣，與分頁導覽同層顯示，不再放在跨越後分類區與全文結果區的共用區塊。

### 9.2 分頁導覽

- 全文結果區上緣提供分頁導覽，至少包含「第一頁」、「上一頁」、目前頁碼、總頁數、「下一頁」及「最後一頁」。
- 有足夠空間時，應同時顯示目前頁前後的可直接選取頁碼；空間不足時可以省略部分頁碼，但不得省略目前頁及總頁數。
- 位於第一頁或最後一頁時，無法使用的導覽操作須呈現停用狀態。
- 執行有效的新全文查詢、套用或移除後分類條件、清除條件、切換資料版本，均回到結果第1頁。
- 只有切換頁碼不得改變全文查詢、後分類條件、分類值排序或結果排序。
- 從完整紀錄返回列表時，保留原頁碼與全文結果區的捲動位置。
- 全文結果區上緣的結果筆數及分頁導覽應在該區內固定可見；捲動結果內容時不隨內容離開可視範圍。

### 9.3 結果列表

每筆結果至少顯示：

- `Data_SPEC.md`指定的結果標題、識別、時間及位置欄位。
- `Data_SPEC.md`指定的完整全文內容，不截取上下文或摘要。
- 命中關鍵詞醒目標示。
- 開啟完整紀錄的操作。

每頁筆數、顯示順序、主要排序、非數值排序及同值排序規則由`Data_SPEC.md`指定。

共用排序行為：若資料規格指定的排序欄位為「整數或文字」，可解析為整數的值按數值及指定方向排序；無法解析為整數的來源文字排在所有數值之後，再按來源字面值排序。所有同值紀錄最後使用資料規格指定的次要排序欄位，以確保分頁結果穩定。

### 9.4 完整紀錄

- 顯示該筆紀錄的全部原始欄位及原始值。
- 顯示目前資料版本及來源識別碼。
- 全文中的查詢詞可醒目標示。
- 同一筆全文有多處命中時只顯示一筆完整全文，並醒目標示所有命中位置。
- 從完整紀錄返回列表時，保留全部全文查詢式、頁碼、排序及後分類條件。

### 9.5 空結果

- 允許查詢或累積過濾後得到 0 筆。
- 保留全部全文查詢式及全部後分類條件。
- 清楚顯示目前條件沒有符合資料。
- 不自動撤銷最後條件。
- 使用者可移除後分類條件，或按下「重新查詢」清除全部條件並返回資料庫全覽。

### 9.6 含標記全文的閱讀與高亮

- 結果列表與完整紀錄的主要閱讀區顯示完整可讀正文，不顯示原始 Tag 語法，也不截取摘要；所有 Tag 片段依下列規則著色。搜尋仍使用純文字索引。完整紀錄另提供可展開的「原始標記全文」，以純文字方式顯示完整來源值，滿足原始值回查需求；原始值檢視不套用正文的背景色與搜尋高亮。
- 高亮依8.7純文字中的命中區間呈現；所有正文命中處均標示。同一命中跨越一個或多個 Tag 邊界時，仍須完整高亮。
- 不可直接在原始標記字串中插入高亮標籤；不得使 Tagname、Term 或 RefId 被高亮或破壞標記結構。以安全文字節點及受控的高亮元素呈現。
- NOT 排除項不產生高亮；重疊命中區間合併，且每篇文件只顯示一次。沒有正向命中詞的純 NOT 查詢不產生高亮。
- 所有已標記的正文片段均須有背景色，包含尚未查詢、未套用 Tag 過濾，以及目前未在左側選取的 Tag 類別。未標記文字維持一般正文樣式，不因字面相同而自動著色。
- 已套用 Tag 過濾時，以「Tagname＋Term」對照正式條件，加強標示全部符合的標記片段；同一 Term 對應不同原文或 RefId 時仍一致處理。不同 Tagname 即使 Term 相同，也不能誤套用強調樣式。
- 多個 Tag 類別及多個 OR 值同時作用時，所有符合正式條件的片段都須強調，不只強調目前下拉選單所選類別。Metadata 過濾不直接觸發 Tag 強調。
- 尚未按「過濾」的勾選不改變正文樣式；取消草稿不改變已套用的強調。移除 Tag 條件、清除全部後分類或重新查詢後，相關片段恢復一般 Tag 背景，仍保持可辨識。切換「後設資料／內文標籤」不影響正式條件的強調。

#### 9.6.1 樣式層級與重疊規則

| 正文片段狀態 | 顯示要求 |
|---|---|
| 未標記、未命中 | 一般正文 |
| 已標記，未用於目前 Tag 過濾 | 清楚可辨的柔和背景色，保留易讀文字對比 |
| 符合已套用 Tag 過濾 | 較強的背景／前景對比，另加外框或其他非單靠顏色的識別 |
| 全文搜尋命中 | 使用一致的搜尋高亮樣式 |
| 同時為 Tag 片段與搜尋命中 | 保留 Tag 背景及過濾外框，命中部分另用高對比底線等獨立樣式標示，不互相覆蓋 |

- 樣式層級參考附件的背景區塊與醒目片段；不要求逐一複製附件所有色碼。具體色碼由共用介面樣式集中管理，不寫入資料專屬規格，也不要求每種 Tag 都使用不同顏色。
- 提供簡短圖例，說明一般 Tag、已套用 Tag 與搜尋命中的樣式；不得只靠顏色傳達是否為過濾條件。文字與背景須有足夠對比，正文維持可閱讀的字體大小。
- 搜尋只命中 Tag 內部分文字時，Tag 背景涵蓋完整元素內容，搜尋強調只涵蓋實際命中區間。跨 Tag 或未標記區域的搜尋命中可分段呈現，但命中範圍不可缺漏。
- 顯示依純文字與標記位置切分安全文字節點；不得重新以字串取代方式標記同名詞，不改寫來源 XML，也不增加巢狀來源 Tag。
- 長片段可正常換行，背景與強調須跨行完整顯示，不截斷文字、不增加正文空白，也不得造成水平溢出。
- 不新增屬性浮窗或 RefId 外部導覽。

## 10. 後分類分析

### 10.1 基本介面

- 後分類區不顯示「後分類」區域標題，直接由欄位選擇控制開始。
- 原「分類欄位」標籤統一改為「後分類欄位」。介面文案、無障礙名稱及測試名稱皆使用新名稱。
- 以一個下拉選單提供多種後分類類別。
- 欄位選單前提供固定二選一的分段控制，不使用下拉選單。兩個可見選項依序固定為「後設資料」及「內文標籤」，不得改用英文 `Metadata`／`Tag`、資料集自訂名稱或其他同義文案。
- 「後設資料」對應內部 Metadata 後分類，「內文標籤」對應內部 Tag 後分類。選取狀態必須清楚可見，並提供正確的鍵盤操作、焦點樣式及無障礙選取狀態。
- 切換「後設資料／內文標籤」只改變目前可選的後分類欄位與分類值，不清除已套用條件、其他類別草稿或排序；詳細狀態規則見10.10。
- 選擇類別後，顯示該類別的分類值、可用筆數及勾選控制。
- 「後分類欄位」保留為控制區唯一的全寬主要下拉選單。
- 後分類欄位下方使用單列緊湊控制列：左側顯示「排序」及小型排序下拉選單，右側顯示次要操作「清除全部」。桌面版不得讓排序與清除各自占用一個全寬區塊。
- 排序只改變目前類別的分類值顯示順序，不改變查詢結果、分類條件或分類筆數。「清除全部」的行為仍依10.7及10.10，不因縮短文案而改變範圍。
- 勾選分類值不立即改變結果。
- 使用者變更勾選後，畫面下方浮動顯示「過濾」與「取消」操作；按下「過濾」後才套用該次選擇。
- 可切換其他類別並重複操作。
- 長期顯示的提示文字縮為「同欄多選採 OR」。勾選後才出現的「過濾／取消」已足以表達確認流程，不再長期顯示「勾選後按『過濾』」。
- 選單、分段控制及分類值列採緊湊尺寸；不得以大面積留白表達層級。控制仍須保留足夠的點按範圍、文字可讀性及清楚焦點狀態。

### 10.2 分類值顯示排序

「排序」下拉選單提供以下四個選項：

1. 依標題升冪。
2. 依標題降冪。
3. 依文件數升冪。
4. 依文件數降冪。

排序規則如下：

- 「標題」指目前後分類項目的顯示文字；採符合中文及數字閱讀順序的自然排序。
- 「文件數」指第10.5節規則計算出的目前可用紀錄筆數。
- 依標題排序時，標題相同的項目再依文件數排序；升冪時採文件數升冪，降冪時採文件數降冪。
- 依文件數排序時，文件數相同的項目一律依標題自然升冪排序，以維持穩定且可預期的順序。
- 預設值為「依文件數降冪」，延續本規格原有的分類值排序方式。
- 每一後分類欄位可在當次瀏覽器使用期間保留自己的排序選擇；切換欄位再返回時恢復該欄位最後使用的排序。
- 排序操作不會自動套用尚未確認的勾選，也不會重設目前頁面中的全文查詢或其他後分類條件。

### 10.3 Metadata 後分類查詢邏輯

- 同一後分類欄位勾選多個值時採 `OR`。
- 不同後分類欄位之間採 `AND`。
- 單值與多值欄位皆可勾選多項。
- 在條件表示式中，Metadata 欄位名稱一律以大括號標記，例如 `{供養人身份}`。
- 小括號 `(`、`)`用於組合條件及表示運算優先範圍，不是欄位名稱標記。
- 條件表示式由後分類介面依使用者勾選內容產生；本版不提供使用者手動輸入 Metadata 條件表示式的功能。
- 為避免語法歧義，匯入的任何來源欄位名稱均不得以 `(` 或 `{` 開始。

例：

```text
({分類欄位A} = 值1 OR {分類欄位A} = 值2)
AND {分類欄位B} = 值3
AND ({多值欄位C} = 值4 OR {多值欄位C} = 值5)
```

### 10.4 累積過濾

設全部已套用的全文查詢形成的集合為 `R0`：

1. 第一個分類欄位的選取條件作用於 `R0`，得到 `R1`。
2. 第二個分類欄位的選取條件作用於 `R1`，得到 `R2`。
3. 後續條件依相同方式持續縮小結果。
4. 任意時點的結果等於全部全文查詢與全部作用中分類條件的交集。
5. 系統重新計算時應由 `R0` 加上目前全部條件得到結果，不依賴不可重現的畫面暫存集合。

### 10.5 分類值筆數

使用者開啟某一後分類類別時：

- 保留全部全文查詢及其他分類欄位的作用中條件。
- 暫時排除目前類別自己的既有條件。
- 在上述集合中計算該類別各值的可用紀錄筆數。
- 多值欄位以「包含該獨立值的紀錄數」計算。
- 同一紀錄對同一分類值最多計一次。
- 選項筆數可高於最終套用全部條件後的筆數。
- 每個筆數皆可開啟或導向構成該數值的紀錄集合。
- 分類值的畫面順序依第10.2節的「排序」下拉選單決定。
- 所有分類值依來源字面值處理，不建立特殊狀態清單或排除功能。
- 單值欄位的空白值若存在，介面顯示為`（空白）`。
- 多值欄位拆分後的空項目不形成分類值。

### 10.6 勾選、取消與套用後顯示

- 使用者第一次改變目前後分類欄位的勾選狀態時，後分類區下方浮動顯示操作列。
- 浮動操作列包含主要操作「過濾」及次要操作「取消」，並固定於後分類區可視範圍下緣，不因分類值清單捲動而消失。
- 「過濾」將目前勾選值設為該欄位的正式條件，與其他欄位條件共同重新計算結果及分類筆數，並把結果頁碼重設為第1頁。
- 若目前沒有勾選任何值，按下「過濾」等同移除該欄位的正式條件，並恢復顯示該欄位全部可用分類值。
- 「取消」只放棄目前尚未套用的勾選變更，恢復該欄位最近一次已套用的選擇；若該欄位尚無正式條件，恢復為全部未勾選。
- 按下「過濾」或「取消」後，若已沒有尚未套用的變更，浮動操作列即隱藏。
- 同一欄位套用過濾後，再次查看該欄位時，分類值清單只顯示該欄位已勾選並已套用的項目，不顯示未選項目。
- 套用後仍須顯示各已選項目的勾選狀態與依第10.5節計算的可用紀錄筆數，並可依第10.2節重新排序。
- 若要改選該欄位未被選取的項目，使用者須先移除該欄位條件，再重新選擇；移除後恢復顯示該欄位全部可用分類值。
- 套用後只隱藏未選分類值，不刪除來源資料、分類索引或其他欄位條件。

### 10.7 條件管理

- 每個已套用的後分類欄位顯示為條件籤。
- 條件籤應顯示欄位名稱及所有已選值。
- 同欄位的多個 OR 值應在同一條件籤或同一條件群組呈現。
- 使用者可單獨移除任一欄位條件。
- 提供「清除全部後分類」功能。
- 移除條件後，立即依全部全文查詢與剩餘條件重新計算結果及所有分類筆數。

### 10.8 重新查詢

- 一般的「執行查詢」是在目前結果上再查詢，不清除既有條件。
- 「重新查詢」按鈕清除全部全文查詢及後分類條件。
- 清除後回到現行資料版本的全部紀錄，並重設頁碼。
- 「重新查詢」不刪除或變更資料版本及原始資料。
- 全文語法錯誤時不清除既有有效結果及條件。

### 10.9 後分類欄位

下拉選單內容與順序由`Data_SPEC.md`定義。每個後分類欄位必須在資料集設定中定義：

- 顯示標籤。
- 單值或多值。
- 資料型態。
- 預設排序方式；未另定時採「依文件數降冪」。
- 是否供後分類使用。

### 10.10 Metadata 與 Tag 的共用規則及差異

本節將10.1–10.9的控制、累積過濾、排序與條件管理擴展至兩種後分類；10.3的 Metadata 特定表示法維持原義。

| 項目 | Metadata 後分類 | Tag 後分類 |
|---|---|---|
| 分類名稱 | 已核准的資料欄位 | Data_SPEC指定的顯示名稱；未指定時使用Tagname原名 |
| 分類項目 | 欄位值，依資料設定決定是否拆分 | Term 屬性值，不以元素內文或 RefId 取代 |
| 分類識別 | 類型 Metadata 加欄位識別 | 類型 Tag 加 Tagname |
| 值的合併 | 依原有規則 | 同一 Tagname、相同 Term 合併；不同 Tagname 不合併 |
| 同類別多選 | OR | OR |
| 跨類別／跨類型 | AND | AND |

1. 例如全文查詢、Metadata 的供養人身份及 Tag 的 PersonName 條件，三者取文件集合交集；Tag 過濾結果仍是一篇一筆的文件列表。
2. 同一文件中 `<person term="揚法師">道揚</person>` 與 `<person term="揚法師">揚師</person>` 形成同一分類項目「揚法師」，文件數為1。相同 Term 搭配不同 RefId 仍為同一分類項目。
3. 「文件數」為包含該 Tagname／Term 的不重複文件數；同一文件內相同分類值不論出現幾次，皆只計一次。
4. **已確認**：Tag 選單使用文件數，預設依文件數降冪，維持既有四種排序選項。不使用出現次數，亦不要求另行計算或保存出現次數統計；分類計數、排序及回查皆以文件為單位。
5. 兩種分類皆沿用10.5的計數範圍：保留全文及其他所有分類條件，暫排除目前類別自身條件。因此分類筆數可能高於最終結果筆數。此為既有規則，本輪不改成只在最終結果中計數。
6. 沒有某 Tag 的文件不貢獻該類別項目，但仍保留在未套用該 Tag 條件的結果中；不建立「未標記」分類值。無任何 Tag 的版本在 Tag 區顯示「此版本無 Tag 後分類」。
7. 套用某 Tag 類別後，只顯示已選取並套用的 Term；移除該類別條件後恢復全部可用值，沿用10.6。
8. 條件籤顯示 `後設資料：供養人身份 = 比丘` 或 `內文標籤：標記人名 = 道揚`，避免同名混淆；內部仍保存 Metadata／Tag 類型及穩定識別碼的結構化條件，不解析中文畫面文案來重建條件。
9. 「清除全部後分類」同時清除兩類已套用與草稿條件，保留全文查詢；「重新查詢」清除全文及兩類分類條件。
10. 切換「後設資料／內文標籤」或類別時，按「內部類型＋類別」保留各自的草稿勾選與排序；返回時恢復。浮動「過濾／取消」只作用於目前類別，不自動套用其他草稿。切換本身不改變結果或頁碼。
11. Tag 的介面顯示名稱由使用者在`Data_SPEC.md`指定，用於類別下拉選單與條件籤；未指定時使用 Tagname 原名。修改顯示名稱不改變來源 Tagname、分類識別、Term 聚合或既有條件。分類項目仍顯示 Term，不受類別顯示名稱影響。

## 11. 基礎統計與視覺分析（本版不製作）

本版不製作獨立的分類分布、統計圖表、時間分析、交叉分析或統計結果回查。後分類選項旁為完成篩選所需的可用紀錄筆數，不視為本章的統計分析功能。

## 12. 資料版本管理

### 12.1 版本資料

每個成功版本至少保存：

- 系統版本識別碼，採專案內單調遞增的四位數格式：`v0001`、`v0002`、`v0003`。
- 匯入日期與時間。
- 原始檔名及檔案指紋。
- 原始 Excel。
- 工作表名稱及欄位結構快照。
- 紀錄數。
- 正規化資料及全文索引。
- 原始含標記全文、純文字、Tag 紀錄與位置、Metadata／Tag 索引，以及解析規則與資料包格式版本。
- 驗證結果。
- 與前一版本的差異摘要。
- 現行／封存狀態。

### 12.2 現行版

- 同一時間只有一個現行版。
- 日常查詢與分析預設只使用現行版。
- 新版完整驗證及建立成功後才可成為現行版。
- 新版失敗不得影響原現行版。

### 12.3 還原

- 使用者可把封存版本重新設為現行版。
- 還原不刪除任何版本。
- 還原行為及時間須留下紀錄。
- 還原不建立新的資料版本；系統只切換現行版本指標，並在操作記錄中保存還原時間、還原前版本與還原後版本。

### 12.4 比較

版本比較至少包含：

- 總紀錄數變化。
- 新增紀錄。
- 刪除紀錄。
- 共同紀錄中變更的欄位。
- 各欄位變更筆數。
- 單筆紀錄的前後值。

版本比較使用`Data_SPEC.md`指定的唯一鍵配對不同版本的紀錄。

只有標記或屬性改動也視為全文來源欄位變更，不能只比較純文字。舊版無 Tag 資料可保留為純文字版本；新格式上線前須在副本驗證讀取或重建衍生索引，不靜默改寫舊版來源。切換版本時清除全文與兩類分類條件、草稿及頁碼，避免使用前一版的 Tag。

## 13. 匯出

目前已實作版本不提供全文查詢結果、一般分類結果、版本差異或查詢條件匯出。

視覺化專區「資料表格」提供CSV匯出，詳見VISUALIZATION_SPEC.md第18.6及19章。此功能限資料表格，不自動擴充至全文結果、版本差異或其他匯出。

## 15. 狀態與錯誤處理

### 15.1 匯入狀態

建議狀態：

- 待驗證
- 驗證失敗
- 待確認
- 建立中
- 可使用
- 現行版
- 封存

最終名稱及允許轉換待確認。

### 15.2 錯誤訊息

- 指明檔案、工作表、列號、欄位及問題原因。
- 區分阻擋錯誤與可接受警告。
- 不以一般「處理失敗」取代可行的具體訊息。
- 匯入失敗時提供修正方向，但不得自動修改研究資料。

- 指出布林語法錯誤位置及原因。
- 保留上一個有效查詢與結果。
- 不因一次無效查詢清除後分類狀態。

## 16. 非功能需求

### 16.1 隱私

- 原始Excel及尚未發布的資料版本預設只在管理者本機處理及保存。
- 只有管理者明確執行發布時，核准的靜態版本資料包才上傳至公開網站。
- 公開網路版不要求帳號，不保存或傳送使用者的查詢式與後分類條件。
- 公開靜態資料包可被任何網站使用者下載；不得發布不可公開的欄位或資料。

### 16.2 可追溯與可重現

- 每筆分析結果可追溯至版本、紀錄、欄位及原始值。
- 相同版本、查詢式及分類條件必須產生相同結果。
- 條件籤應保留足以重現目前分析的資訊。

### 16.3 效能

本版支援及驗收上限：

- 單一資料版本最多 50,000 筆紀錄。
- 最多 100 個欄位。
- 單一 Excel 檔案最大 50 MB。
- 單筆全文最大 200,000 個 Unicode 字元。
- 所有上限皆由匯入驗證，超過時阻擋匯入並顯示實際值與限制值。

基準環境為 Apple Silicon M1、8 GB 記憶體、SSD、macOS 及 Chrome 正式版，平台已完成啟動且不包含首次下載或安裝時間：

- 本專案基準資料的全文查詢、再查詢、後分類套用及條件移除，95%操作在500毫秒內完成；基準資料量由`Data_SPEC.md`記錄。
- 在上述支援上限的效能測試資料中，全文查詢及後分類操作的95%回應時間不超過2秒。
- 結果翻頁的95%回應時間不超過500毫秒。
- 50 MB、50,000筆、100欄的 Excel 匯入與索引建立在120秒內完成。
- 兩個各50,000筆版本的差異比較在120秒內完成。
- 效能測試不包含瀏覽器首次啟動、備份壓縮或檔案從外接／網路磁碟複製的時間。

### 16.4 易用性

- 使用者不需要建立統計工作表。
- 本版不顯示查詢語法說明入口；語法錯誤仍須提供具體位置與原因，使使用者可以修正查詢式。
- 目前版本、查詢式、結果筆數及分類條件須清楚可見。
- 0 筆結果及匯入錯誤不得造成無法返回的狀態。

### 16.5 備份與可攜性

- 程式檔與使用者資料目錄分離，更新程式不得覆寫資料目錄。
- 使用者可建立單一 ZIP 備份套件。
- 備份套件包含資料集設定、所有靜態版本資料包、版本紀錄、各版本原始 Excel、操作記錄、平台版本及 SHA-256 校驗清單。
- 還原前先驗證套件結構、平台相容版本及所有檔案校驗值；驗證失敗不得改變目前資料。
- 還原會完整取代目前專案資料，因此執行前自動建立一份還原前備份。
- 平台更新前自動建立備份；只自動保留最近5份更新／還原前備份，手動建立的備份不自動刪除。
- 專案搬移以備份套件完成：在新位置安裝相同或相容的平台程式，再匯入備份套件。
- 備份與搬移不屬於第13章排除的查詢或分析結果匯出。

### 16.6 瀏覽器與作業系統

- 主要支援環境為 macOS 14以上版本。
- 主要瀏覽器為 Google Chrome 最新正式版及前一個主要版本。
- 所有功能、視覺及效能驗收均以 Chrome 為準。
- Safari、Firefox、Edge及其他作業系統不列入本版正式驗收；若可使用視為非保證相容。

### 16.7 啟動、停止與更新

- 提供可雙擊的一鍵啟動程式；啟動本機服務後自動以 Chrome 開啟平台首頁。
- 本機服務只監聽迴送位址，不開放區域網路或外部網路連線。
- 重複執行啟動程式時不得啟動第二個服務；應改為開啟既有平台頁面。
- 提供平台內「停止服務」操作及可雙擊的停止程式；停止前完成必要檔案寫入，不涉及資料庫關閉。
- 程式更新採替換程式核心、保留獨立資料目錄的方式。
- 更新前自動備份；更新失敗時保留原資料及可繼續使用的舊版程式。
- 若更新需要資料結構遷移，須先在備份副本驗證成功，再套用至正式資料。
- 公開網路版只發布靜態前端與已驗證的版本資料包，不部署後端程式或資料庫。
- 網路版更新必須先在本機完成建置、驗證與備份，再發布新版目錄與現行版指標。

- 已完成三個具實質差異的介面雛形比較。
- 使用者已確認採用A版「研究工作臺」作為後續開發外觀，B、C版不繼續使用。

#### 16.8.1 後分類與全文結果雙區域

- 查詢列及作用中條件列以下，分成左側「後分類區」與右側「全文結果區」。
- 兩區各自具有垂直捲動；捲動任一區域不得改變另一區域的捲動位置。
- 兩區之間提供可拖曳的寬度調整分隔線，使用者可在不遮蔽主要操作的範圍內增加或減少後分類區寬度。
- 後分類區的預設寬度為原A版設計寬度的130%；以原型280像素為基準時，預設約為364像素。
- 桌面版後分類區最小寬度為280像素、最大寬度為可用內容寬度的50%；全文結果區最小寬度為520像素。若視窗不足以同時符合最小寬度，介面改採窄版排列，不得以水平溢出破壞全文閱讀。
- 寬度調整只影響畫面配置，不改變查詢條件、分類條件、資料版本或結果頁碼。
- 後分類區不顯示「後分類」標題；「後設資料｜內文標籤」分段控制、「後分類欄位」選單及排序／清除緊湊控制列固定於左區上緣；「過濾／取消」浮動操作列固定於左區下緣；只有中間的分類值清單捲動。
- 桌面版上緣控制由三層構成：第一層為「後設資料｜內文標籤」分段控制；第二層為單一全寬「後分類欄位」選單；第三層為同列的排序小型選單與「清除全部」次要按鈕。提示文字置於第三層下方，採單行「同欄多選採 OR」。
- 建議控制高度為42至48像素，分類值列高度為44至52像素；實作可依字體及無障礙需求微調，但應以左區在一般桌面高度顯示更多分類值為驗收目的。
- 「清除全部」不得使用與「過濾」相同的主要按鈕樣式，也不得占滿左區整行；若窄版空間不足，第三層可合理換行，但仍維持緊湊間距與操作順序。
- 結果筆數與分頁導覽固定於右區上緣；只有其下方的全文結果清單捲動。

## 17. 測試計畫

### 17.1 測試資料原則

### 17.2 共用邏輯測試

#### Excel 匯入

1. Excel 的第一個工作表作為正式資料來源，工作表名稱不影響匯入。
2. 共用框架不檢查固定名稱的必要欄位；個別平台只核對建立時已核准的資料集欄位結構。
3. 唯一鍵空白或重複時阻擋匯入。
4. 任一欄位名稱以 `(` 或 `{` 開始時阻擋匯入，並指出問題欄位。
5. 額外的統計或說明工作表不影響匯入。
6. 欄位新增、刪除或改名時拒絕直接升版。
7. 匯入失敗不影響現行版。
8. 原始 Excel 與解析資料均正確保存。
9. 只有警告而沒有阻擋錯誤時，不要求使用者確認並繼續完成匯入。

#### 多值與來源狀態文字

1. 半形分號正確拆分。
2. 拆分值前後空白不影響分類匹配。
3. 同一紀錄內重複值只計一次。
4. 原始多值字串及順序仍可回查。
5. `無`、`缺`、`未明`等來源文字不互相合併。
6. 改變多值項目的來源排列順序不影響分類結果或分類筆數。

#### 全文查詢

1. 單一關鍵詞以連續字串命中。
2. `A AND B` 只回傳同時包含兩詞的紀錄。
3. `A OR B` 回傳至少包含一詞的紀錄，且不重複。
4. `NOT A` 排除包含 A 的紀錄。
5. 驗證 `NOT → AND → OR` 優先順序。
6. 括號正確改變運算順序。
7. 不合法語法顯示錯誤且保留上一個有效結果。
8. 第二輪全文查詢只在第一輪結果中搜尋。
9. 在已有後分類條件時執行新全文查詢，保留後分類條件並繼續縮小結果。
10. 各輪全文查詢式及其套用後筆數按順序顯示。
11. 「清除輸入」只清空查詢框，不改變條件或結果。
12. 「重新查詢」清除全部全文查詢及後分類條件，回到現行版本的資料庫全覽。
13. 在 0 筆結果上再次查詢仍為 0 筆，直到使用者按下「重新查詢」。
14. `and`、`And`、`AND`及其他大小寫組合產生相同運算結果。
15. 雙引號內的空白、括號及`AND`、`OR`、`NOT`按字面查詢。
16. 反斜線可跳脫下一個語法字元；未閉合引號及末尾反斜線顯示語法錯誤。
17. 空白查詢在資料庫全覽時代表全部紀錄，在已有條件時不改變目前結果。
18. 查詢區不顯示「查詢語法」文字、連結、展開控制或說明區塊；查詢框提示文字與查詢語法功能維持可用。

#### 結果列表

3. 分頁前後不得遺漏或重複紀錄。
